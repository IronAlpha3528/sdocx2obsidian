# Software Requirements Specification (SRS)
**Project Name:** `sdocx2obsidian`  
**Document Version:** 2.0.0  
**Focus:** Functional & Product Requirements  

---

## 1. Product Overview & Scope

### 1.1 Purpose
`sdocx2obsidian` converts modern Samsung Notes (`.sdocx`) files into Obsidian-compatible Markdown (`.md`) files, preserving the inline reading order of typed text, images, and audio recordings. It operates in two official modes:
1. **Command Line Interface (CLI):** A local Python CLI tool for desktop batch conversion.
2. **Web Converter:** A client-side, zero-upload browser application executing 100% in WebAssembly via Pyodide.

### 1.2 Target Workflow
1. The user manually exports their notes from Samsung Notes as `.sdocx` files into a local directory.
2. The user runs the CLI tool, specifying the source directory of `.sdocx` files and the destination Obsidian directory.
3. The tool converts each `.sdocx` file into a Markdown note and extracts any embedded media into a note-specific relative subfolder.

### 1.3 Scope Boundaries

| Feature Area | In-Scope (Supported) | Out-of-Scope (Ignored/Excluded) |
| :--- | :--- | :--- |
| **Input Formats** | Modern Samsung Notes `.sdocx` files | Legacy `.sdoc` and `.snb` formats; direct `AppData` scraping |
| **Text Content** | Raw plain typed text and paragraph breaks | Rich-text styling (bold, italics, headers, colors, checklists, tables) |
| **Visual & Ink Content** | Embedded raster images (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`) | S-Pen ink, vector drawings, shapes, canvas stroke data, PDF drawings, and `.spi` drawings (recognition is not currently implemented; these types are skipped) |
| **Audio Content** | Embedded voice/audio recordings (`.m4a`, `.amr`, `.mp3`, `.wav`, `.ogg`) | Audio transcription or waveform generation |
| **Non-Media Attachments** | (None) | PDF attachments, document attachments, and non-image/non-audio files |
| **Metadata** | Original `.sdocx` filename (used as the note title) | Creation/modification timestamps, tags, folders, YAML frontmatter |

## 2. Functional Requirements

### FR-01: Command-Line Interface & Batch Input
* The system shall operate as a Python CLI script accepting two directory paths:
  * **Source Directory (`--source` / `-s`):** The folder containing exported `.sdocx` files.
  * **Destination Directory (`--dest` / `-d`):** The target Obsidian folder where converted notes and assets will be written.
* If the destination directory does not exist, the tool shall create it automatically.
* Source `.sdocx` files shall strictly be read and never modified or deleted.

### FR-02: Plain Text Extraction
* The system shall extract all typed text from each `.sdocx` note as raw plain text.
* Rich-text formatting tags shall be stripped, leaving only the underlying plain text characters and standard paragraph breaks.
* Non-image objects such as S-Pen ink, vector drawings, shapes, canvas stroke data, PDF drawings, PDF attachments, and document metadata are not currently implemented and shall be skipped with a non-fatal warning or treated as out-of-scope.

### FR-03: Contextual Inline Media Placement
* The system shall preserve the exact sequential order in which text blocks, images, and audio clips appear within the original Samsung Note.
* If an image or audio recording appears between two paragraphs in the Samsung Note, its Obsidian embed link shall appear in that exact position between those two paragraphs in the generated `.md` file.

### FR-04: Obsidian Inline Embedding Syntax
* Both extracted images and extracted audio files shall be embedded inline using Obsidian's native Wikilink embed syntax:
  * `![[<AssetFolderName>/<HashedFileName.ext>]]`
* Links shall always use forward slashes (`/`) to ensure compatibility across Windows, macOS, and Linux Obsidian vaults.

### FR-05: Relative Asset Subfolder & Media Naming
* Each converted note's media files (images and audio) shall be saved in a dedicated relative subfolder located in the same destination directory as the `.md` file, named `<NoteName>_Assets/`.
* Extracted media files shall retain the internal hashed filenames and extensions generated by Samsung Notes (e.g., `a8f9d21b.m4a`, `4c91e0b2.png`).
* **Clean Vault Rule:** If a note contains only typed text and zero embedded media files, the tool shall **not** create an empty `<NoteName>_Assets/` folder.

### FR-06: Note Naming & Versioned Collision Resolution
* The output Markdown file shall be named directly after the source `.sdocx` filename stem (e.g., `Meeting Notes.sdocx` becomes `Meeting Notes.md`).
* If a file named `<NoteName>.md` or a folder named `<NoteName>_Assets/` already exists in the destination directory, the tool shall append a sequential version number in parentheses—starting at `(1)`—to **both** the Markdown file and its asset folder:
  * Markdown file: `<NoteName> (1).md`
  * Asset folder: `<NoteName> (1)_Assets/`
* All inline media embeds inside `<NoteName> (1).md` shall automatically point to `![[<NoteName> (1)_Assets/<hashed_filename.ext>]]`.

### FR-07: Non-Blocking Error Handling & Reporting
* If an individual `.sdocx` file is corrupted, cannot be opened, or contains unreadable content, the CLI shall:
  1. Log a clear, human-readable warning to the terminal identifying the problematic file.
  2. Skip the corrupted file without leaving partial/broken output files in the destination directory.
  3. Continue processing the remaining `.sdocx` files in the batch.
* Upon completing the batch, the CLI shall display a summary showing the total number of files processed, succeeded, and skipped/failed.

### FR-08: In-Browser Client-Side Execution & Privacy (Web Mode)
* In web mode, conversion shall execute 100% inside the user's browser runtime using Pyodide WebAssembly.
* No note content, filenames, or binaries shall ever leave the user's browser.
* Issue reporting links shall be completely sanitized, containing zero note text, titles, or filenames.

### FR-09: Web Session Safety & Memory Caps (Web Mode)
* Web conversion shall enforce pre-read safety limits:
  * Maximum 50 MB per `.sdocx` archive.
  * Maximum 100 MB total session byte budget.
  * Maximum 5 files per conversion session.
* Files exceeding limits shall be rejected before decompression without freezing the browser tab.

### FR-10: Combined Vault ZIP Output (Web Mode)
* Completed conversions in web mode shall bundle all converted notes and asset directories into a single root-level ZIP file.
* Text files shall be compressed (deflated); media binaries shall be stored uncompressed; archive paths and timestamps shall be deterministic.
* Unpacking the ZIP into an Obsidian vault shall immediately resolve all wikilink embeds.

## 3. Acceptance Criteria

1. **Text & Media Interleaving:** Given a valid `Lecture.sdocx` containing Paragraph A, an image `img1.png`, Paragraph B, and an audio clip `voice1.m4a`, when the tool runs, then `Lecture.md` contains Paragraph A, followed by `![[Lecture_Assets/img1.png]]`, followed by Paragraph B, followed by `![[Lecture_Assets/voice1.m4a]]`, and `Lecture_Assets/` contains both binary files.
2. **Text-Only Note:** Given a valid `QuickNote.sdocx` containing only typed text, when the tool runs, then `QuickNote.md` is created and `QuickNote_Assets/` is not created.
3. **Collision Handling:** Given `Lecture.md` already exists in the destination folder, when `Lecture.sdocx` (with `img1.png`) is converted again, then `Lecture (1).md` and `Lecture (1)_Assets/img1.png` are created, and `Lecture (1).md` embeds `![[Lecture (1)_Assets/img1.png]]`.
4. **Fault Tolerance:** Given a folder with $2$ valid `.sdocx` files and $1$ corrupted `.sdocx` file, when the tool runs, then $2$ Markdown notes are generated, $1$ warning is logged to the terminal, and the CLI exits cleanly.
